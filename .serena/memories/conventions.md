# Code conventions and ownership

Authoritative owners: `docs/conventions.md`, `docs/code-quality.md`, `docs/elixir.md`, `docs/phoenix.md`, `docs/action-reuse.md`, `docs/testing-approach.md`. Read affected owners/service guide before changes, and a module's `@moduledoc` before adding functions.

- Contexts/domain logic live under `lib/zaq/`; LiveViews/controllers/plugs/workers orchestrate rather than own business rules. Use public context boundaries, Ecto changesets and schemas; BO must not access persistence/integrations directly.
- Fallible public APIs use `{:ok, result}` / `{:error, reason}`. Public context/behaviour/adapter functions get `@spec`; document non-obvious invariants. Predicates end `?`, not `is_`. One responsibility per module; do not split solely for line count or add nested modules to files.
- New BO role invocations use `Zaq.Agent.Events`, `Zaq.Engine.Events`, `Zaq.BO.Events`, or appropriate Channels/other domain Events helpers. Helpers construct Events and use NodeRouter; a reusable Action does not waive distributed boundaries. Canonical incoming/outgoing message structs prevent provider-envelope leakage.
- Runtime dependency overrides: `opts \\ []` at meaningful side-effecting public boundaries, `Zaq.Config.get(:zaq, key, default, opts)`, `config: TestConfig` in tests. Routed calls carry override in Event opts. Resolve modules/values once, pass them explicitly internally; long-lived processes retain startup dependencies. Avoid test-only production hooks or opts bags on pure helpers.
- Use Req for new HTTP work even though a legacy HTTPoison dependency remains. Keep provider details behind integration behaviours and bridge implementations. Routing helpers remain stateless; process ownership belongs in runtime modules.
- Action discovery: check `lib/zaq/agent/tools/registry.ex`, Action declarations throughout lib, domain APIs, Events helpers, workflow Action/Steps. Registry is an explicit agent allowlist, not the complete Action catalog. Record reuse/extend/new/local-only decision and contract/actor/side-effects/verification evidence; no operation changes => justified not applicable. Missing essential Actions are prerequisites, not hidden local fallbacks. Prefer established validated execution (`Jido.Exec.run/3`), not direct `run/2`; workflow execution stays under StepRunner. No automatic tool exposure.
- Retryable workers/side effects must be idempotent, with appropriate job uniqueness. Oban args carry durable IDs rather than large payloads. State transitions with broadcasts/audit belong in one lifecycle owner (e.g. Ingestion.JobLifecycle).
- Tests exercise real internal code and real sandboxed DB, mock external behaviours only. Prefer per-process Mox, explicit allowances, async isolation; global mutations need dedicated async:false tests and restoration. No external network calls. NodeRouter mocks must match Events per test, not blanket-success stubs. Add StreamData properties for broad-input invariants and authorization defaults; never weaken assertions to hide regressions.
- Secrets/access policy remain governed by `docs/services/system-config.md` and owning service docs. Nil person identity is not authorization; model-supplied fields are not trusted actor context.
